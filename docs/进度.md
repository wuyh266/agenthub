### 本轮修的坑（README / 面试素材）

- **`.gitignore` 全文件失效（重要）**：每一行 pattern 的真实字节是 `<6个空格><pattern><CR>`。
  - 前导空格：git 不 trim pattern 的前导空白 → pattern 变成 `"      .env"`
  - 尾部 CR：git 只 trim 尾部的空格和 tab，**不 trim 回车** → CRLF 编辑多出一个 `\r`
  - 装饰行（`    ── 凭据 ──`）不是 `#` 注释 → 被 git 当成 pattern 解析
  - 三者叠加 → 包括 `.env` 在内**所有规则都不匹配**（`git check-ignore` 返回 1）。当时没放 .env
    所以没暴露，一旦放了 key，`git add .` 会把凭据推上 GitHub。
  - 已重写为顶格 pattern + LF 行尾 + `#` 注释。教训：`.gitignore` 要在 WSL 侧编辑，别用 Windows 记事本。
- **`ImageScaling` 只能走构造函数**：字段 `endpoint`/`client` 未导出且必填。
  - `&imageprocessing.ImageScaling{}` 编译能过，但 endpoint 为空串 → `http.NewRequestWithContext`
    报 `unsupported protocol scheme`；`client` 为 nil → `Do` 空指针 panic。
  - 分界线是**零值可用性**：`mock.Echo` 是空结构体（零值即完整状态，且 `struct{}` 占 0 字节），
    所以 `Echo{}` 可用；`ImageScaling` 依赖外部地址，零值不可用 → 必须给构造函数。
  - 另一件独立的事：接收者类型决定"进接口带不带 `&`"。Echo 是值接收者 → `Echo{}` 满足接口；
    ImageScaling 是指针接收者 → 只有 `*ImageScaling` 满足。
- **`question` 命令行覆盖**：`os.Args[0]` 是程序自身路径，所以判断 `len(os.Args) > 1`（不是 `> 0`，
  否则不传参数时 `os.Args[1]` 越界）。参数传的是**自然语言任务**，不是工具参数——那是 LLM 的活。
